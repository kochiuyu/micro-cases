OPS-22 · 香港 · 虚构场地 · 15–20分钟 · 关键路径 · 进度压缩 · 浮动时间

缩短最耗时的活动，项目就能提前完工吗？

一项活动做得更快，场地不一定能更早开放

项目进度管理指南指出，项目何时完工，取决于各项活动之间的依赖关系，不能只看各项活动需要多长时间。给某项活动增加资源，最终交付时间也可能不变，因为另一条路径仍然更晚完成。进度调整后，决定完工时间的路径也可能改变。

以下场地、活动、工期和报价均为本案例原创的课堂假设。这不是实际施工进度表，也不代表任何具名场地的安全规程。

课堂决策

虚构的课堂情境。 你负责协调香港一间活动室的小型非结构性装修。业主希望在已批准的赶工预算内尽早交付。基础费用已经落实。今天你可以购买 一个 价值6,000港元的赶工方案：把B从四个工作日缩短到两个，或者把C从八个工作日缩短到六个。额外调来的专业团队不会从其他活动抽调人员。第一轮不能只买部分方案，也没有其他赶工选项。

所有活动都必须完成。每项活动都必须等所有列出的紧前活动完成后才能开始。A完成后，B和C可以并行；D在B完成后开始；E必须等到 C和D都完成。B只负责准备家具区；C包括装饰板的制作、运输，以及在独立展示区内就位。两项活动由不同团队负责，场地空间也足够，因此可以并行。材料和具备资质的人员均已到位。计算时假定各项活动的工期固定，没有资源冲突、返工或额外延误。

按累计工作时间计，从0开始：一项耗时两个工作日的活动若在时点0开始，就会在时点2完成，紧后活动随即可以开始。所有团队使用同一份工作日历；这些数字不是日历日期。开工前所需的许可均已办妥。E包括余下的必要检查和交付：两天工期不能省略或缩短，放行条件也不能绕过或放宽。所有方案都维持同样的质量和安全作业安排。

第二轮 · 多了一项资料

无论第一轮投票选了什么，接下来大家都以同一份计划为起点。 业主已批准B方案，B现在计划用时两天。工作还没开始；这只是修订后的计划，不代表活动室已经完工。C仍需八天，D仍需五天。

现在又有一笔单独的赶工预算，金额为6,000港元。你最多再买一个方案：把C从八天缩短到六天，或把D从五天缩短到三天。C仍可按原报价购买，D的额外团队则是刚刚有了档期。两个方案都符合相同的安全和质量要求，其他工期和依赖关系都不变。你也可以两个都不买，把钱留下。E仍需两天。目标仍是在获批预算内尽早交付；案例没有给出每提前一天能带来多少收入。

你的决策

既然B已缩短到两天，第二笔6,000港元你会花在C上、花在D上，还是都不买？算出每种选择下的项目完工时间，并指出在你推荐的方案中，哪条路径决定完工时间。

梳理通向交付的两条路径

两条完整路径分别是A → B → D → E和A → C → E。赶工前，前一条路径的工期为2 + 4 + 5 + 2 = 13天 ，后一条为2 + 8 + 2 = 12天。两条分支都必须完成，所以完工时间由较晚完成的那条路径决定：13天，既不是两条路径工期之和，也不是它们的平均值。

在这份简单的进度计划中，耗时13天的那条路径就是 关键路径 。这条路径上的活动没有推迟的余地，任何一项推迟都会导致项目晚完工。C是耗时最长的单项活动，但它在时点10完成，D则在时点11完成。C有一天的 总浮动时间：只要其他活动按计划进行，C即使晚一天完成，也不会推迟整个项目。非关键活动并不是可有可无，也不能掉以轻心。

第一次购买：看项目能提前几天

把C缩短到六天：A → C → E变为10天，但A → B → D → E仍需13天。项目仍在时点13完工，花这笔钱并不能让交付提前。

把B缩短到两天：A → B → D → E变为11天，A → C → E仍需12天。项目在时点12完工，提前一天。按题设目标，应买B。B虽然缩短了两天，但现在由另一条分支决定完工时间，所以整个项目只提前一天。

关键路径变了

B缩短后，A在时点2完成，B在时点4完成，D在时点9完成，C在时点10完成。E最早只能在时点10开始，到时点12完成。现在A → C → E是关键路径。按修订后的完工时间算，B和D各有一天总浮动时间，但这是同一条路径上共享的一天，并不是两项活动各推迟一天也不影响完工。

两条路径都要盯住。一旦另一条路径变得更长，再缩短原关键路径，可能也无法进一步提前完工。

第二次购买：重新计算，不要照搬

B已经缩短到两天。若再把D缩短到三天，A → B → D → E就需要9天。经过C的路径仍需12天，因此整个项目还是12天完工。两个方案都不买，完工时间也还是12天。

如果改为把C缩短到六天，A → C → E变为10天，A → B → D → E仍需11天。现在整个项目的完工时间为 11天，又由A → B → D → E决定。要尽早完工，就选C。两个方案合计花费12,000港元，比原来13天的计划提前两天。不能因为两项活动各缩短两天，就说整个项目提前了四天。

第二个方案花费6,000港元，让项目再提前一天。从财务上看值不值，要看提前交付的价值以及可能涉及的其他成本；案例并未提供这些信息。案例确定的是预算允许的最快进度，而不是利润最大的投资方案。

进度计划是模型，不是承诺

在路径汇合处，要等最后一项必需的紧前活动完成，才能开始紧后活动。赶工或出现延误后，要重新检查整个进度网络。浮动时间是在给定假设下算出来的，不意味着可以不满足安全、质量或合同要求。

实际工期和资源可用情况都可能变化。承诺开放时间之前，要确认额外团队、活动之间的依赖关系、尚未完成的检查和更新后的进度预测。如果某项必要检查未通过，即使到了算出的时点，也不能放行。增加人手不一定能缩短每一类活动的工期。

教师说明

建议用时15–20分钟：三分钟看活动依赖表，四分钟完成第一轮投票并计算两条路径的工期，五分钟讨论第二笔预算，再用三到八分钟讨论浮动时间和商业含义。学生明确给出第一轮答案之前，不要揭晓后续信息。画出A分成B → D和C两条分支，再汇入E。不要把并行分支的工期相加。

问选择C的学生：家具这条分支的工期会变吗？问选择B的学生：为什么活动缩短两天，项目却只提前一天？接下来让所有学生都采用B已缩短的修订计划，确保第二轮在同一基础上比较。不要求正式做逆推计算；如有需要，可在学生作出决策后讨论那一天的浮动时间。

OPS-03讲的是受各工位产出率约束的重复串行生产；OPS-04讲的是如何在一台机器上安排多个重复批次的顺序；OPS-21讲的是如何根据提前期倒推物料需求时间。本案例是一次性项目的进度网络，有并行路径也有汇合点。不要把关键活动等同于耗时最长的单项活动，也不要建议压缩安全检查时间。

课堂决策所需的资料，上文已经齐备。来源只供选读，用来交代出处和背景。

非结构性场地装修及其工期、依赖关系、预算和专业团队赶工方案均为原创虚构设定。五项活动及其工期：A为2、B为4、C为8、D为5、E为2；紧前活动：A无，B等A，C等A，D等B，E等C和D。采用同一工作日历，累计时间从0起算；各活动按完成后立即可开始的关系衔接，无时滞；团队各自独立，无资源冲突；工期确定，工作范围、质量和安全要求不变。开工前所需许可均已办妥；E包含强制性的两天检查与交付，不得缩短或跳过，仍须通过检查才能放行。第一轮只能买一个方案：B从4改为2，或C从8改为6，各需6000港元。第二轮假定B方案已在开工前获批，另有6000港元预算，可将C从8改为6，或将D从5改为3，最多选一个；其余条件不变。两条路径的基准工期为13/12；只买B时为11/12，完工时间为12；只买C时为13/10，完工时间为13；买B和D时为9/12，完工时间为12；买B和C时为11/10，完工时间为11。基准计划中C的浮动时间为1天；实施B方案后，B和D各有1天总浮动时间，二者共享，不可相加。所有数字仅作说明，并非实测生产率或实际采购报价。目标是在预算内尽早交付，而非按财务净现值决策。查阅了五项有实质参考价值的机构或专业资料，或其中的相关章节；两篇PMI论文是不同的文献，并非相互独立的实地研究。案例正文可独立使用。
