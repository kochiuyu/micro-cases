統一輸入資料，讓例外個案清晰可見

要做到一致，也要為不同情況設立處理流程

有關公共服務設計的指引建議，只問切題的問題、測試各條處理路徑，並協助無法提供預期答案的使用者。流程指引也指出，輸入資料與後續工序息息相關。以下虛構的支援中心要探討的是：統一受理流程能否保留有實質意義的例外個案，而不致演變成一堆不受規管的特殊要求？

課堂決定

你負責管理位於香港、虛構的 Harbour Parcel Support。中心處理跨境包裹配送狀態的行政查詢，不負責放行貨物、決定是否清關，也不處理危險品申報。這些職責以及所有現行的安全、私隱和法律管控措施，均不在這次重設的範圍內。

目前，兩個小組為同一項服務使用不同的受理表格。員工每次轉介查詢，都要重新對照欄位名稱。管理層希望統一識別資料，減少誤轉其他小組的情況，而不是削減人手。兩個負擔得起的方案都沿用現有系統、同一筆有薪培訓撥款，以及現有的獲授權小組。

A 對所有查詢一律使用同一份固定表格，並預設交由同一個小組處理。B 為常規及例外個案分設表格，兩份表格共用核心欄位；員工須先選對表格，才輸入詳情。服務主管尚未梳理各類查詢的分佈，也未測試任何一個方案。兩個方案均保留必要的核查及審計記錄。

第二輪 · 多了一項資料

一組經覆核的虛構個案共有200宗查詢：184宗是常規的包裹追蹤查詢，16宗涉及退貨組已受理的退貨。兩類查詢互不重疊。後者須由退貨組而非追蹤組處理。受理查詢的員工可在現有記錄中看到已受理退貨的參考編號。

在一次用來診斷問題的重演中，A 將全部200宗查詢分派給追蹤組，當中16宗退貨查詢其後須更正分派並轉介。在 B 方案下，一名受過培訓的覆核員按該參考編號逐宗選擇表格，全部200宗查詢均分派正確。這只證明在這次重演中有必要區分兩類查詢，並不代表員工在實際工作中總能選對。

第三個可行方案 C 保留統一的受理流程，並設一道必答的分派問題：現有記錄是否顯示退貨已獲受理？答「是」，便顯示退貨參考編號欄位，並把查詢分派給退貨組；答「否」，則分派給追蹤組。選「無法確定」時，查詢會交由現有的獲授權支援主管釐清，絕不會在沒有提示的情況下分派給追蹤組。

C 可在同一筆撥款額度內利用現有系統推行。支援主管已確認有足夠的處理能力應付試行；釐清情況並不容許跳過必要的核查。員工保留最初收到查詢的時間，向客戶解釋尚未確定之處，並記錄最終分派去向。試行不能保證即時釐清情況，也不能保證縮短解決查詢所需的時間。

你的決定

現在你會試行哪個方案？計算重演中 A 首次分派出錯的比率。訂明 C 的例外個案處理規則、負責人和監察方式，並說明即使分派去向不同，哪些環節仍應統一。

講解 · 統一有用的共通部分

在這組經覆核的查詢中，A 分派錯誤的比率為 16/200 = 8%；92% 一開始便分派得當。常規查詢佔比高，不代表可以忽略少數個案。整體數字可能掩蓋集中在某個可辨識類別的系統性問題。這些是分派結果，並非查詢解決率或客戶滿意度。

試行 C，保留共通的欄位定義、必要的證明資料、時間記錄及審計記錄。只按已識別的情況調整必要的問題和分派去向。標準化是訂立可反覆遵循的規則，例外個案也一樣；性質有實質差異的查詢，並不需要用完全相同的方式處理。

講解 · 劃定例外個案的界線

以現有記錄所載的退貨受理狀態為準，不要籠統地請人描述有甚麼不尋常。記下參考編號，把查詢轉介至指定的退貨組，並在對方接手前繼續負責。狀態不明的查詢交由支援主管處理。留空不得在沒有提示的情況下當作答「否」。

不要讓自由填寫的文字成為任意分派的依據，也不容許客戶自行編造受理參考編號。員工不應單憑有人想退回包裹，就推斷退貨已獲受理。這項記錄只用來確認查詢所屬的行政類別，並不代表客戶享有任何清關、退款或配送方面的權利。

講解 · 保留另一個有理據的選擇

如果分設表格能讓職責更清晰，而員工又能可靠地選對表格，B 仍是有理據的選擇。共用欄位定義本身已做到一定程度的標準化。C 毋須在回答分派問題前選擇表格，但這只是有待驗證的設計假設，並不證明一個介面總比兩個優勝。

重演證實，按 A 所列的預設規則分派，會有查詢被派錯小組。重演並無量度採用 C 時填報要花多少工夫、狀態不明的情況有多常見，或一般員工的實際表現。個案亦沒有提供足夠依據，證明可以節省現金開支，或證明客戶滿意度會因而提升。

講解 · 不只測試欄位，也要測試分派路徑

推出前，用貼近實際情況的記錄測試答「是」、答「否」、狀態不明及更正答案的各條路徑。確認更改答案後，分派去向會隨之更新，不會留下已不適用的隱藏資料。確保操作指示持續可見，並提供方便使用者求助的途徑；讓員工用平日的工具參與測試。

在範圍有限的試行期間，按類別統計首次派錯小組而須轉介的個案，並記錄待釐清個案的積壓情況、由收到查詢至有人接手及至解決所需的時間、欠缺的證明資料，以及客戶要花的工夫。未解決的查詢也要計算在內。與服務主管一起檢視新出現的例外個案，不要在未經核查下悄悄增設分支。若分派表現或管控轉差，便應停止或修訂試行。

教師說明

先請學生說明共通的輸入標準，再畫出三條分支，並指出每次交接由誰接手。把已確認受理的退貨與狀態不明的個案分開。釐清期間仍須由最初收到查詢的一刻起繼續計時，免得表格看似井然有序，卻掩蓋了等候時間。

OPS-08 調整一個實體包裝步驟，讓遺漏之處顯現；OPS-23 把輪候中的工作分派給符合資格的員工。本個案改變的是分派前收集哪些資料，以及如何在規則約束下處理例外個案。所有支援中心、數目、處理能力及成本假設均屬虛構；來源指引提供的是設計原則，而非承運商的表現證據。
