IS-36 · 香港 · 15–20分鐘 · 對外共享 · 接收者身分驗證 · 便於使用的存取控制

資料已加密，共享連結卻能讓人讀取？

加密不等於限定閱覽名單

儲存時加密和傳輸時加密都能保護資料，但誰能取得可讀內容，取決於共享設定。香港電腦保安事故協調中心提醒，不應單靠難以猜測的 URL 來保密。下文的設計公司、檔案、報價和檢查均屬虛構，沒有使用任何真實的客戶資料、帳戶、連結或登入憑證。

課堂決定

你管理一家虛構的香港設計公司，正準備一份尚未公開的包裝概念簡報，交由客戶指定的兩名成年審閱者審閱。客戶只授權這兩人在為期七天的審閱期間閱覽，其他人一概未獲授權。兩人不得編輯或轉發簡報，設計公司也未獲授權公開這份作品。

兩個擬議流程採用同一項獲批准的雲端服務，資料儲存時加密，連線亦經加密。兩者都可用瀏覽器閱覽，不可編輯，亦不設下載按鈕。存取權限均在七天後自動失效，管理員也可提早撤銷。簡報存放在獨立位置，沒有繼承權限、群組權限、其他連結授予的權限，也沒有任何原已存在的外部存取權限。

A 採用「知道連結的任何人」設定，接收者毋須登入。B 則要求以指定接收者的帳戶登入，並核對登入身分是否在只有兩人的存取名單上。這些帳戶已經建立並完成驗證。B 在開放閱覽前須測試是否便於使用；公司不會假定每名審閱者都能完成登入流程。

這一輪審閱，A 的費用為400港元，B 為1,000港元，均包括設定、檢查和支援。兩個方案均有足夠預算，只要通過測試，便能趕及限期。一名同事傾向選 A，因為兩個方案都標榜加密，而 A 可省卻登入的麻煩。目前尚未開始正式共享。

你的決定

按客戶明訂的閱覽對象限制，你會暫時選擇哪個流程？說明加密、到期失效和接收者身分驗證各有甚麼作用，並各訂一項開放閱覽前須做的保密測試和易用性測試。

第二輪 · 多了一項資料

在一次受控演練中，公司使用測試簡報和公司測試帳戶。一名不在名單上的測試人員收到轉發的 A 連結，毋須登入便可閱覽簡報。改用 B，同一人登入不在名單上的帳戶後，存取要求遭拒。兩項檢查均沒有涉及實際未獲授權的人士或客戶資料。

其中一名指定審閱者無法每次都順利完成 B 原來的驗證碼輸入步驟，因為畫面要求把驗證碼手動逐格重輸，並禁止貼上。該審閱者可在同一部裝置上使用自己的身分驗證工具。取消身分查核雖然可免卻這項不便，卻等於放棄對閱覽對象的限制，而不是令這項控制更易使用。

服務支援另一個畫面，可在有標籤的欄位貼上或自動填入完整驗證碼，亦支援鍵盤操作。在這次虛構演練中，兩名審閱者都用慣常的工具完成登入並閱覽測試簡報。不在名單上的測試人員仍被拒絕存取。B 的報價已包括這個替代畫面，身分驗證要求維持不變。

公司亦檢查了 B 的提早撤銷權限和七天後到期失效機制。每次權限終止後，無論是全新的存取請求，還是已開啟的工作階段提出的新內容請求，均遭拒絕。公司再次核查存取名單及其他可能取得權限的途徑。這是針對個案所訂設定得出的結果，並非指刪除任何連結都必然能移除所有權限。

兩個流程都無法抹去截圖，或抹去別人已讀到的資料。指定審閱者仍須遵守原有的不得轉發指示。個案沒有量化保密事故的發生概率、預期損失或財務回報。開放閱覽前，如接收者身分驗證不成功，或審閱者無法順利存取，公司便會延後共享，在客戶授權範圍內修正流程。

你的決定

你會維持還是改變原來的選擇？說明轉發連結的檢查證實了甚麼、修訂後的登入流程如何維持對閱覽對象的限制，以及撤銷權限後有哪些資料無法收回。額外的600港元是計算得出的財務回報，還是符合既定要求的成本？

講評 · 分清三項控制措施

加密保護儲存中的數據和通訊內容，防範特定的外洩情況；它並不決定服務應否向持有連結的人顯示簡報。身分驗證確認帳戶身分；授權則核查該身分是否有權閱覽這份檔案。B 同時採用兩者；按個案設定，A 只憑是否持有連結決定能否閱覽。

到期失效限制的是存取時間，而非有效期內誰可以閱覽。只要 A 的連結仍然有效，不在名單上的人也可以使用轉發的連結。因此，縮短有效期和使用難以猜測的網址，都不能滿足客戶只容許指定接收者閱覽的要求。無論怎樣估算連結被轉發的可能性，都不能取代這項明確限制。

講評 · 選 B，但不代表萬無一失

選擇 B，採用經測試的無障礙登入方式。這一輪 B 的費用為1,000港元，比收費400港元的 A 高600港元。兩個方案都在預算之內，但只有經測試的 B 符合按身分限定共享對象的要求。這項差額並不是量化的投資回報，也不是對可避免損失的估算。

轉發連結的檢查釐清了一個重要分別：即使持有 B 的 URL，不在名單上的帳戶也不能憑此獲准閱覽。這不證明帳戶不會被盜用，也不證明獲授權的審閱者不能拍下屏幕。這些虛構檢查只為這項具體的流程決定提供依據，並不構成一般性的保安認證。

講評 · 讓獲授權者能順利使用流程

原來的驗證碼輸入介面要求手動照抄，造成障礙。容許貼上或自動填入，改變的是操作方式，而非誰可獲准存取，身分驗證要求也沒有改變。測試服務支援的替代畫面時，由指定審閱者使用自己慣用的工具操作。不要以共用帳戶、向員工透露驗證碼或改用不設限制的連結作為權宜之計。

兩名審閱者順利完成演練，不代表人人都能無障礙使用，也不代表完全符合相關標準。應繼續提供支援；如裝置、輔助工具或登入步驟有變，便須重新評估。若有人無法完成獲授權的流程，應修正流程或延後共享，不要在未有交代的情況下擴大獲准閱覽的範圍。

講評 · 撤銷權限有其限度

確認閱覽名單、檔案範圍、到期時間，以及所有仍可能授予存取權限的途徑。移除一個連結，不一定會移除直接授予、繼承或由其他連結授予的權限。個案明訂沒有這些其他途徑，測試亦已核實這一點。應檢查全新的請求和仍在進行的工作階段如何運作，不要單憑設定畫面上的標示改了便下結論。

在經測試的設定下，撤銷權限可阻止其後透過服務存取資料，卻無法刪除先前的截圖、抹去別人記住的內容，或收回另行保留的副本。只供閱覽和停用下載按鈕，都不能保證內容不被複製。應維持客戶對分發的限制，只共享獲授權審閱所需的資料。

教師說明

第0–4分鐘：在板上分清加密、身分和權限。第4–8分鐘：公布轉發連結的測試結果。第8–12分鐘：在不改變閱覽對象的前提下，消除手動照抄驗證碼造成的障礙。第12–17分鐘：說明到期失效、撤銷權限和防止複製各有甚麼局限，然後解釋600港元的成本差額是否合理。

這是紙上設計練習。學生不得建立連結、傳送檔案、更改權限或使用真實登入憑證。虛構服務集合了個案指定的功能；本個案不是產品設定指南。評分應着重學生是否提出有條件開放閱覽的決定，以及具體檢查方法，而不是能否承諾絕對保密。

來源與個案假設 · 選讀

課堂決策所需的資料，上文已經齊備。來源只供選讀，用來交代出處和背景。

所有人物、設計公司、簡報、設定、成本和測試均屬虛構。兩名審閱者已有經驗證的帳戶。一份獨立存放的檔案沒有其他對外授權途徑。兩個方案均採用加密，開放存取七天，可提早撤銷權限，可用瀏覽器閱覽，不可編輯，亦不設下載按鈕。只有 B 要求驗證獲授權的指定身分。無障礙替代畫面維持原有的身分驗證要求，容許貼上或自動填入完整驗證碼，並由兩名審閱者測試。每輪1,000港元減去400港元，差額為600港元；個案沒有提供保密事故的發生概率或投資回報。撤銷權限的測試結果適用於這項指定設定下的全新請求及仍在進行的工作階段所提出的請求，不適用於已閱覽或擷取的內容。個案沒有實際共享資料、更改存取權限、進行測試攻擊、處理登入憑證或收集個人資料。

  1. HKCERT · Cloud Storage Security。官方指引區分加密通訊、身分驗證和明確授予的存取權限。指引就難以猜測的 URL 提出的警告，是本個案探討共享問題的由來，並非指有設計公司實際發生資料外洩。
  2. Microsoft Learn · How shareable links work in OneDrive and SharePoint in Microsoft 365。供應商文件說明了向任何人或指定接收者共享的設定，以及可能重疊的授權途徑。個案採用虛構設定，並非聲稱某項產品計劃同時提供所有列出的功能。
  3. NIST · SP 800-207: Zero Trust Architecture · sections 2 and 2.1。第一手技術指引區分存取主體的身分驗證、資源存取的授權，以及持續執行政策。這項小練習並不是對零信任架構的完整評估。
  4. W3C WAI · Understanding SC 3.3.8: Accessible Authentication (Minimum)。官方說明指引涵蓋手動照抄造成的障礙，以及對貼上或自動填入功能的支援。一次流程測試成功，並不證明完全符合無障礙標準。
  5. Dropbox Help · How to set or change shared link permissions。供應商文件解釋到期失效、其他授權途徑，以及封鎖下載的局限。個案參考了這些控制措施的局限，但並不表示虛構服務就是 Dropbox。
