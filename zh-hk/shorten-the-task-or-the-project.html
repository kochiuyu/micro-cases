OPS-22 · 香港 · 虛構場地 · 15–20分鐘 · 關鍵路徑 · 進度壓縮 · 浮動時間

縮短最費時的工序，工程就能提早完成？

工序做快了，場地不一定能提早開放

按項目排程的指引，完工時間取決於工序之間的依賴關係，不能只看各道工序需時多久。即使為某道工序增撥資源，另一組相連的工序仍可能較遲完成，令最終交付時間不變。調整後，決定完工時間的路徑也可能改變。

以下的場地、工序、所需時間和報價均為原創的課堂假設，既不是施工時間表，也不代表任何具名場地的安全程序。

課堂決定

虛構的課堂情境。 你負責協調香港一個活動室的小型非結構性裝修工程。業主希望在已獲批准的趕工預算內，盡早交付場地。基本開支已有撥款。你今天可購買的趕工方案數目是 一個 ，費用為6,000港元。你可選擇將 B 由四個工作天縮短至兩個，或將 C 由八個工作天縮短至六個。額外的專業團隊不會從其他工序抽調人手。首輪不設部分購買，也沒有其他趕工選項。

所有工序都必須完成。每道工序須等所列的前置工序全部完成後才可開始。A 完成後，B 和 C 可同時進行；D 在 B 之後開始；E 則須等以下工序全部完成： C 和 D。B 只負責準備傢俬區；C 則包括製作及運送裝飾板，並將裝飾板放置在另一個展示區。兩道工序由不同團隊負責，場地也有足夠空間，因此可以並行。物料和合資格人員均已到位。計算時假設各工序所需時間固定，沒有資源衝突、返工或額外延誤。

以 0 為起點，按經過的工作時間計算：一道需時兩天的工序若在時點 0 開始，便在時點 2 完成，後續工序可隨即開始。所有團隊採用同一套工作日曆；這些數字不是日曆日期。開工前所需的許可均已取得。E 包括餘下的必要檢查及交付，所需的兩天不可縮短，工序不可略過，放行條件也不可繞過。所有方案均維持相同的品質和安全作業安排。

要讓整項裝修工程提早完成，首輪你會購買 B 還是 C 的趕工方案？分別計算不趕工及採用各方案時的完工時間，不要單憑哪道工序最費時來選擇。

第二輪 · 多了一項資料

不論首輪怎樣投票，接下來一律採用以下排程。 業主已批准 B 的方案，因此 B 現在安排為兩天。工程尚未開始；這是修訂後的計劃，不是說活動室已經完工。C 仍需八天，D 仍需五天。

現有另一筆獨立的趕工預算，金額為6,000港元。你最多可加購一個方案：將 C 由八天縮短至六天，或將 D 由五天縮短至三天。C 的原有報價仍然有效，而 D 所需的額外團隊現在才有空檔。兩個方案均符合相同的安全及品質要求，其他工序所需的時間和依賴關係均不變。你也可以兩個方案都不買，保留這筆款項。E 仍需兩天。目標仍是在獲批預算內盡早交付；個案沒有提供每提早一天可帶來多少收入。

你的決定

B 已縮短至兩天，你會用第二筆6,000港元為 C 還是 D 趕工，還是兩者都不選？計算各選擇的完工時間，並指出哪條路徑決定你所建議方案的完工時間。

找出通往交付的兩條路徑

兩條完整路徑分別是 A → B → D → E 和 A → C → E。趕工前，兩條路徑分別需時 2 + 4 + 5 + 2 = 13天 ，以及 2 + 8 + 2 = 12天。兩條路徑都必須完成，因此以較遲完成的一條為準：工程需時13天，不是兩者的總和或平均值。

在這個簡單排程中，需時13天的路徑就是 關鍵路徑 。這條路徑上任何工序一旦延誤，工程便會延遲完工。C 是最費時的單項工序，但它在時點 10 完成，D 則到時點 11 才完成。C 有一天的 總浮動時間：只要其他工序按計劃進行，C 即使延遲一天，也不會推遲整項工程的完工時間。不是關鍵工序，不等於不必做，也不代表可以放心不理。

首輪購買：計算整項工程可節省多少天

把 C 縮短至六天：A → C → E 改為需時10天，但 A → B → D → E 仍需13天。工程仍在時點 13 完成，交付時間沒有提早。

把 B 縮短至兩天：A → B → D → E 改為需時11天，A → C → E 仍需12天。工程改在時點 12 完成，提早一天。按題定目標，應購買 B 的方案。B 雖然縮短了兩天，整項工程卻只提早一天，因為完工時間改由另一條路徑決定。

關鍵路徑轉移

B 縮短後，各工序的完成時點為：A 在 2，B 在 4，D 在 9，C 在 10。E 要到時點 10 才能開始，並在時點 12 完成。關鍵路徑現為 A → C → E。按修訂後的完工時間計算，B 和 D 各有一天總浮動時間，但這是同一路徑共享的一天，並非兩道工序可以各用一天而互不影響。

兩條路徑都要繼續留意。一旦另一條路徑變得較長，再縮短原來的關鍵路徑，也可能無法進一步提早完工。

第二輪購買：重新計算，不要照搬上次做法

B 已縮短至兩天，若再把 D 縮短至三天，A → B → D → E 便需時9天。經 C 的路徑仍需12天，因此完工時點仍是 12。兩個方案都不買，完工時點同樣是 12。

若改為把 C 縮短至六天，A → C → E 便需時10天，A → B → D → E 仍需11天。整項工程現需 11天，完工時間再次由 A → B → D → E 決定。要盡早完工，應選 C。兩個方案合共花費12,000港元，較原來需時13天的計劃節省了兩個工作天。不能因為兩道工序各縮短兩天，就說整項工程節省了四天。

第二個方案花費6,000港元，讓工程再提早一天完工。財務上是否划算，要看提早交付的價值及其他相關成本；個案沒有提供這些資料。個案找出的是在限制下最快的排程，而不是利潤最高的投資方案。

排程是模型，不是承諾

當多條路徑匯合，須等最後一道必要的前置工序完成，才可開始後續工序。趕工或出現延誤後，都要重新檢視整個工序網絡。浮動時間是在指定假設下算出的排程餘地，並不容許你不符合安全、品質或合約要求。

實際所需時間和可用資源都可能有變。承諾開放日期前，須確認額外團隊、工序依賴關係、餘下檢查和最新預測。如果未能通過必要檢查，即使到了算出的時間，活動室也不能放行。增加人手不一定能縮短每一類工序。

教師說明

預留15–20分鐘：三分鐘看工序依賴表，四分鐘作首輪投票並計算兩條路徑，五分鐘處理第二筆預算，三至八分鐘討論浮動時間及商業上的含意。待學生確定首輪答案後，才揭示第二輪資料。畫出 A 分成 B → D 和 C 兩條路徑，再匯合至 E。切勿把並行路徑的時間相加。

問支持 C 的學生：經過傢俬工序的那條路徑有沒有改變？再問支持 B 的學生：為甚麼工序縮短兩天，整項工程卻只提早一天？然後讓全班採用同一份已縮短 B 的排程，使第二輪比較有一致的基礎。毋須正式進行逆推計算；作決定後，可選擇討論那一天的浮動時間。
